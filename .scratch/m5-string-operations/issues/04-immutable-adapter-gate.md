## What to build

Complete the first M5 acceptance slice: immutable concatenation, byte length, strict byte slicing and literal replace-all work consistently through the core, CLI and freshly rebuilt browser adapter. This ticket supplies adapter contracts and slice-level evidence, not another compiler implementation or final M5 acceptance.

## Acceptance criteria

- [ ] At each optimization level, core/CLI/rebuilt-browser Wasm bytes, WAT and diagnostics agree for matching inputs/options. Basic/Standard/Aggressive retain byte identity with one another; do not require None to equal enabled levels.
- [ ] Cover all four operations, UTF-8 including empty and embedded-NUL text, alias/interned-literal safety, strings held in arrays, strict slice failures, replacement edge cases, selected/no exports and imported functions.
- [ ] New builtin names are rejected as global user-function and host-language registration names; arbitrary nonempty external module/field names remain allowed. Lexical shadows use normal resolution with no noncallable fallback.
- [ ] Positional fixed arity/types, defaults/contracts whitelist rejection, named-call rejection and direct builtin pipeline-stage rejection have consistent diagnostics. Preserve raw spans and first-error ordering for unchanged behavior.
- [ ] Bounded executions establish once-only left-to-right argument effects, validation before fast-path reuse, no rollback of completed effects, retained handles after caught traps, reentry and actual memory growth. Hosts refresh views after growth; valid immutable UTF-8 remains a trusted-host obligation.
- [ ] CLI output destinations remain unchanged on compilation/registration errors. Existing host marshaling remains explicit and copy-based, with no new imports or runtime ownership API.
- [ ] Review compiler frontend/forged-tree/decoded/runtime evidence from prerequisite tickets and record the first slice's contract-to-test evidence without claiming join or final M5 acceptance.
- [ ] Update README.md, grammar.bnf where relevant, docs/limitations.md, docs/runtime-integration.md, docs/browser.md, the M5 roadmap and AGENTS.md to distinguish implemented immutable builtins from pending fragment/join acceptance. Do not update unrelated historical milestone evidence.

- **Direction:** `string_concat(string,string)->string`; `string_byte_len(string)->number`; `string_slice_bytes(string,number,number)->string`; `string_replace_all(string,string,string)->string`. Slices use finite integral `0 <= start <= end <= byte_length`, accept -0, require scalar-boundary endpoints even when empty, and never clamp. Replace-all uses case-sensitive literal nonoverlapping left-to-right matches, no inserted-text rescan, and traps on empty needle. All arguments execute before operation checks, then string validation in argument order, constraints, checked size and necessary allocation. Immutable inputs/aliases are unchanged; initial reuse follows the confirmed narrow policy. No new string UTF-8 scan, general reclamation, fusion, mutable builder, len(string) overload or M4 performance disposition.
