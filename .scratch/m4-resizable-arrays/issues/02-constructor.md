## What to build

Implement `resizable(source)` from source analysis through executed Wasm for `number[]`, `bool[]` and `string[]`. It creates a fresh resize-authorized copy using existing array types and an eight-byte public descriptor. The source and its aliases are unchanged. This slice exposes construction only: no operation may yet relocate or shrink its payload.

## Acceptance criteria

- [ ] Evaluate source once; validate complete outer storage and every copied logical element. Copy mutable slots independently; immutable string values may be shared. Copying another resizable array still creates a distinct collection.
- [ ] Retain a stable descriptor and private authority record keyed by exact handle. Track element kind, logical length, full usable capacity and current owned payload/acquisition authority. Structural validity alone never grants resize authority.
- [ ] Acquire the full selected power-of-two byte capacity, minimum eight bytes even when empty, using the required M3 core internally. Do not treat rounding slack outside the requested extent as usable. Publish only a fully prepared array; failed construction may retain earlier successful unpublished allocations without rollback.
- [ ] Plan internal helper/type/global indices before checked body lowering. Do not expose M3 management exports, test controls or observations. Programs without M4 retain existing bytes/helper order; ordinary literals remain fixed-storage even in M4 modules.
- [ ] Make `resizable` an ordinary-identifier builtin following `len`: reserved global function/host-language name, normal lexical shadowing, positional arity one, no direct builtin pipeline stage. Preserve arbitrary host module/field names and document the newly reserved global-name migration.
- [ ] Preserve exact contextual array typing: `let flags: bool[] = resizable([])` works; unconstrained `resizable([])` defaults to number[]. Placeholder source/result relationships remain region-local; `resizable(_)` alone is ambiguous and callers provide no refinement. Preserve Never, reachability and first-error conventions.
- [ ] Reject constructor use in defaults/contracts, including skipped operands, independently in source checking and forged typed input. Include all-type acceptance/rejection, owned-copy identity/isolation, validator/independent decoded checks, bounded execution and preset parity.
