## What to build

Run final integrated M4 correctness, portability, adapter and measurement gates on stable final sources; publish a contract-to-test map and an explicit release-readiness conclusion. Update supported-versus-proposed status only where current evidence justifies it. Do not infer milestone acceptance from historical M3 results, default Cargo success or stale browser bindings.

## Acceptance criteria

- [ ] Map every confirmed M4 contract to actual frontend, forged-tree, independently decoded, runtime, failure, CLI/browser and measurement evidence. Confirm all predecessor implementation/evidence exits and final-source hashes; report uncovered cases and missing prerequisites as pending.
- [ ] Verify all three array types, copy constructor/authority, contextual/placeholder typing, purity boundaries, fixed-storage rejection, safe pending ordinary/all-five-compound writes, reentry/caught traps, shifting/shrinking iteration and consumed-element validation.
- [ ] Require old valid non-M4 programs to retain bytes/helper layout; account for the intentional `resizable` global-name migration. Check semantic/diagnostic parity across numeric presets, enabled-preset byte identity and adapter byte parity within levels. Preserve import snapshots/export behavior and compatibility fixtures without regeneration.
- [ ] Run offline native tests/Clippy, core wasm32 build, architecture checks, freshly rebuilt browser smoke and full workspace include-ignored suite, plus wasm32 browser Clippy. Record commands, nonzero test counts, ignored coverage, exit codes, tooling versions and exact source revision/dirty state. Stable-source evidence only.
- [ ] Reproduce M4 measurement modes sequentially on the final sources using the measurement blocker's exact commands. Keep observations and uninstrumented timings separate; record costs/limits without claiming general reclamation or bounded total memory.
- [ ] Update `README.md`, relevant ABI/typed-array/runtime/browser/limitations docs, roadmap status and `AGENTS.md` to distinguish implemented subsets from release acceptance. Record unchanged fixed-storage rights, opt-in movable-payload borrow contract, runtime authority, capacity/failure limits and retained object storage.
- [ ] Conclude accepted versus pending explicitly; correctness success does not silently authorize unmeasured performance claims, M2 migration, GC, host ownership registration, new defaults or broader optimization. Do not close/modify unrelated or parent issues.
