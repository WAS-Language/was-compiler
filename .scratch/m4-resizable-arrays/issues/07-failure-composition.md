## What to build

Verify complete M4 authority and operation-failure behavior under adversarial composition, with deterministic failure injection only in private tests. After each trapped operation, prove published arrays remain usable in the same instance. This extends the focused tests required in each feature ticket; it does not postpone basic correctness until here.

## Acceptance criteria

- [ ] Exercise checked numeric/capacity boundaries without huge allocations; negative zero handling, overflow before narrowing and deterministic backing/identity exhaustion where applicable. Validate old state, live contents and later successful use after failures.
- [ ] Require exact registry membership and matching element kind, public payload/length, capacity and current active acquisition authority before mutation. Structural-valid host fabrications never acquire authority. Inconsistent descriptor state traps before publication; private metadata corruption remains outside supported host behavior and is not a security claim.
- [ ] Demonstrate returned-element validation precedes pop/remove mutation; constructor consumes all logical elements while relocation/shifting unreturned elements do not scan. Failed replacement preserves post-argument logical state; argument effects and earlier successful allocations remain, with no sweeping/rollback promise.
- [ ] Exercise payload reuse while outer ordinary/all-five-compound writes are suspended: aliases, receiver rebinding, index effects, captured receivers, recursive/reentrant calls, caught inner traps and later calls. Prove the old reused buffer is not corrupted and compounds retain the pre-RHS old number.
- [ ] Cover shrink-invalidated post-RHS stores, shifting current-index stores and iteration mutation in all three types. Include invalid/unreachable/short-circuited/unexported typed-input rejection and independent decoded check/publication order, not only valid Wasm.
- [ ] Keep private test transport/configuration/instrumentation absent from ordinary production modules. Preserve non-M4 bytes, M2 and M3 private contracts; record unexplained failures as pending, not acceptance.
